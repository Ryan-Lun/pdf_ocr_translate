## 部署架構

```text
使用者瀏覽器
    |
    v
Nginx
    |-- /static/ -> static/
    |
    v
Gunicorn Unix Socket
    |
    v
Flask App
    |-- SQLAlchemy / pyodbc -> MSSQL
    |-- OpenAI / Azure OpenAI -> 翻譯模型
    |-- Triton / PP-Structure -> OCR 或版面服務
    |-- out/ -> 上傳、任務、輸出、模板與翻譯記憶

    |-- uo_regulations_translate.service
    |-- uo_regulations_translate_worker.service
    |-- uo_regulations_translate_log_cleanup.timer
    |-- uo_regulations_translate_template_backup.timer
```

## 主要環境變數

| 參數 | 用途 | 正式環境注意事項 |
|---|---|---|
| `APP_ENV` | 應用環境 | 正式環境設為 `production`。 |
| `AUTO_SCHEMA_MANAGEMENT` | 是否由 app 啟動時自動建表或補欄位 | production 預設為 `0`。 |
| `SECRET_KEY` | Flask session 簽章 | 正式環境必須使用高強度隨機值。 |
| `DATABASE_URL` | SQL Server 連線字串 | 缺少時正式部署不可用。 |
| `DATABASE_SCHEMA` | SQL Server schema | 現有文件建議使用 `translation`。 |
| `AUTH_ENABLED` | 是否啟用登入保護 | 正式環境應設為 `1`。 |
| `AUTH_STUB_ENABLED` | 是否啟用 stub 登入 | 正式環境應設為 `0`。 |
| `AUTHZ_MODE` | 授權模式 | 常用值為 `ad_all_users`。 |
| `OPENAI_API_KEY` | OpenAI / Azure OpenAI API key | 不得提交至 Git。 |
| `OPENAI_BASE_URL` | OpenAI / Azure OpenAI endpoint | 正式環境需明確設定。 |
| `DOC_TRANSLATE_DEPLOYMENT` | 文件翻譯 deployment | 正式環境需明確設定。 |
| `WORD_TRANSLATE_DEPLOYMENT` | Word 翻譯 deployment | 正式環境需明確設定。 |
| `WORKER_*_MAX_RUNNING` | Worker 各類任務併發上限 | 依機器資源與 API 限制調整。 |
| `LOCAL_WORD_PROVIDER_ENABLED` | 是否在 UI 與 worker 啟用地端 Word provider | 停用時設為 `0`，不要求其他 local 設定。啟用時必須同時設定下列三項。 |
| `LOCAL_WORD_BASE_URL` | 地端 OpenAI-compatible `/v1` endpoint | 只在 `LOCAL_WORD_PROVIDER_ENABLED=1` 時必要；startup 只檢查設定完整，不檢查網路連線。 |
| `LOCAL_WORD_API_KEY` | 地端模型 credential | 只在 local provider 啟用時必要，不得寫入 Git、job metadata、artifact、log 或 alert。 |
| `LOCAL_WORD_MODEL` | 地端模型名稱 | 只在 local provider 啟用時必要，需與 endpoint 支援的 model 名稱一致。 |
| `LOCAL_WORD_STAGE_2_ENABLED` | 地端 Word Stage 2 post-edit | 預設啟用；Stage 2 失敗可保留 Stage 1，但 Stage 1 最終失敗會使 job failed。 |
| `LOCAL_WORD_REQUEST_CONCURRENCY` | 單一 local Word job 的請求併發 | 顯存有限時建議設為 `1`；沿用既有 Word worker concurrency，不建立 provider-specific queue。 |
| `LOCAL_WORD_REQUESTS_PER_MINUTE` | local Word request RPM 節流 | 依地端模型吞吐量調整，建議先使用低值驗收。 |
| `LOCAL_WORD_ENABLE_THINKING` | 是否傳送模型 thinking mode 設定 | 依地端模型支援情況設定；不影響 Cloud provider。 |

## Local Translation Provider 部署驗收

Local Word provider 是選擇性功能，設定 `LOCAL_WORD_PROVIDER_ENABLED=0` 時，production startup 不會要求 local endpoint、credential 或 model。設定為 `1` 時，三項設定缺一即停止 startup，錯誤會直接列出缺少的參數。

Startup validation 不會連線探測地端 endpoint，因此 endpoint 暫時離線不會阻止 Web 或 worker 啟動；實際 local job 連線失敗、timeout 或 retry exhaustion 會 fail-closed，記錄安全 System Error 並依既有 Teams Alert 設定通知，絕不改送 Cloud provider。

部署後至少驗證：

- Cloud Word job 仍能完成。
- Local `auto`／`zh` 到 `en` job 能套用 Department Glossary 與 Translation Memory。
- 多檔上傳使用同一個 provider/model snapshot。
- 不支援的語言方向會在建立 job 時拒絕。
- Local Stage 2 fallback 保留 Stage 1，且 endpoint 離線時 job 失敗、不會呼叫 Cloud client。
- job metadata、lifecycle artifact、System Error、Teams Alert 與 log 不含 endpoint、API key、原文或譯文。

完整命令與人工驗收案例請參考 `24-WordLocalBatchRunner操作與驗收指引.md`。


## 部署流程摘要

1. 確認 `.env` 包含資料庫、OpenAI/Azure、LDAP/AD 與 session 必要設定。
2. 使用 `uv sync --frozen` 同步 Python 虛擬環境。
3. 執行 Alembic migration，例如 `alembic upgrade head`。
4. 執行 `flask --app app.py schema-preflight` 檢查必要資料表與欄位。
5. 執行 `flask --app app.py seed-bootstrap` 初始化角色與初始管理員。
6. 使用 `bash deploy.sh` 安裝或更新 systemd unit、Nginx site 並重啟服務。
7. 透過 `systemctl status`、`journalctl` 與瀏覽器頁面確認服務狀態。
