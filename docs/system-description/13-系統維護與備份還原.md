## Legacy job state 同步救援

依程式碼 `app/services/jobs.py`、`app/services/operations_service.py` 與 `scripts/sync_jobs_from_disk.py`，系統以 SQL Server 的 `jobs` 資料表作為新任務狀態的權威來源。舊版任務若只有檔案系統中的 `job_meta.json`、`batch_status.json` 或相關輸出檔，可以使用 `job-state-sync` 指令將 legacy JSON 狀態受控地同步回 SQL Server。

正式同步前，應先執行 dry-run：

```bash
cd /home/NE025/pdf_ocr_translate
.venv/bin/flask --app app.py job-state-sync --dry-run
```

確認 `errors=0` 且 `would_create`、`updated`、`skipped` 的數量符合預期後，再執行正式同步：

```bash
cd /home/NE025/pdf_ocr_translate
.venv/bin/flask --app app.py job-state-sync
```

輸出欄位判讀如下：

| 欄位 | 說明 |
|---|---|
| `scanned` | 掃描到的 job 目錄數量。 |
| `created` | 本次實際建立的 SQL job row 數量。 |
| `updated` | 本次補齊既有 SQL job row 缺失欄位的數量；既有 SQL 狀態不會被 legacy JSON 覆蓋。 |
| `would_create` | dry-run 模式下，若正式執行將建立的 SQL job row 數量。 |
| `skipped` | 已有完整 SQL row，或該 snapshot 標記為 SQL-first 而不應由 JSON fallback 接管的 job 數量。 |
| `errors` | 同步失敗數量；若大於 0，需依逐筆 detail 排查後再重跑。 |

每筆明細會以 `job_state_sync_detail` 顯示 `job_id`、`action` 與 `reason`。常見 `reason` 包含：

| reason | 說明 |
|---|---|
| `missing_sql_record` | 磁碟有 legacy job 狀態，但 SQL Server 沒有對應 row。 |
| `filled_missing_sql_fields` | SQL row 已存在，但補齊了缺失的非狀態欄位，例如任務名稱或擁有者。 |
| `sql_exists_complete` | SQL row 已存在且核心欄位完整，因此跳過。 |
| `sql_first_snapshot_missing_sql` | 檔案標記為 SQL-first snapshot，但 SQL row 遺失；為避免新任務退回雙資料源，不由 JSON fallback 接管。 |

注意事項：

- `--dry-run` 不會寫入 SQL Server。
- 正式同步只用於舊任務救援或資料庫重建後補登 legacy job 狀態。
- 新任務仍必須以 SQL Server 為權威狀態來源，JSON 檔只作為 snapshot 或診斷資訊。
- 若 `errors` 大於 0，不應直接重啟批次作業，應先確認對應 job 目錄與 JSON 檔是否可讀且內容有效。

## 模板備份

模板備份由 `scripts/backup_templates.sh` 執行，備份範圍包含 `document_templates` DB 匯出、`out/templates/jobs/` 與舊版備用 JSON 檔。備份檔預設輸出至 `backups/templates/`，命名格式如下：

```text
<hostname>_templates_<YYYY-MM-DD_HHMMSS>.tar.gz
<hostname>_templates_<YYYY-MM-DD_HHMMSS>.tar.gz.sha256
```

預設最多保留最新 3 份備份，可由 `TEMPLATE_BACKUP_MAX_FILES` 調整。

## 模板還原

標準還原流程：

```bash
cd /home/NE025/pdf_ocr_translate
APP_ROOT=/home/NE025/pdf_ocr_translate \
ENV_FILE=/home/NE025/pdf_ocr_translate/.env \
bash scripts/restore_templates.sh /path/to/<backup-file>.tar.gz --yes
```

還原會覆蓋目前模板資料。依既有文件，還原前應先確認備份檔與 checksum，並暫停使用者對模板的新增、編輯與刪除操作。

## 備份限制

模板備份不包含：

- `.env`、API key、DB 連線字串或 LDAP 密碼。
- 整個 MSSQL database。
- 一般使用者上傳檔、一般 OCR / 翻譯 job 輸出。
- `logs/`、`.venv/`、`PaddleX/` 或其他大型 runtime 目錄。
